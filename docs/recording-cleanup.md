# 录屏保存与回收

任务结束时停止 scrcpy，将录屏整理成 MP4，转换成功后删除原始 MKV。横竖屏切换和长任务可能生成多个分段，`recording.json` 保存播放顺序。

## 自动回收

服务启动时先等待异常录屏恢复，再检查录屏；之后默认每小时检查一次。默认保留任务结束后 7 天的录屏；总容量超过 10 GiB 时，从最旧录屏开始回收。

自动回收仅删除录屏、分段、残留 MKV 和播放清单。任务结果、日志、截图、笔记、报告、分析证据和回放测试资料继续保留。页面显示“录屏已自动回收”，仍可查看任务结果和步骤截图。

运行中、正在整理或恢复的录屏不会回收。最近一小时有录屏写入的目录暂时保留，下一次检查再处理。无数据库引用的旧录屏，只在目录格式明确属于 ARTEMIS 时回收；无法确认归属的文件保留。

可以在 `.env` 或启动服务的环境变量中配置，修改后重启 ARTEMIS 服务：

```dotenv
ARTEMIS_RECORDING_CLEANUP_ENABLED=true
ARTEMIS_RECORDING_RETENTION_DAYS=7
ARTEMIS_RECORDING_MAX_GIB=10
ARTEMIS_RECORDING_CLEANUP_INTERVAL_SECONDS=3600
```

保留天数和容量必须大于 0，检查间隔至少 60 秒。关闭开关会停止后续自动回收，已经删除的录屏无法恢复。容量上限仅针对管理范围内的录屏，不是整个 traces 目录的大小；正在使用的文件可能使录屏暂时超过上限。

## 清空历史与单条删除

“清空历史”删除历史数据库记录和对应任务文件，包括网页、MCP、SDK 任务目录及旧版本遗留的孤立任务目录。探索配置、手工流程模板、回放测试资料保留。有运行中或排队任务时提示先结束任务。

单条删除按会话及完整目录名匹配，不用名称前缀匹配其他任务。文件删除失败时保留数据库记录，报告已删除文件数、释放空间和失败项，下一次重试继续处理。

所有删除限定在服务配置的 traces 根目录内，不跟随符号链接。自定义输出到该目录之外的录屏不会自动删除；手动清空遇到这种引用时会报告未清理项。录屏回收结果和失败原因写入服务日志。
